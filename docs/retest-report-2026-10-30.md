## 四、遗留与新发现的问题

### 4.1 情节记忆召回完全没动（P1，下次该修的第一件）

`episode.py` 无任何改动，复测与昨晚一致：

```
recall@1 = 0%    recall@3 = 41.7%    MRR = 0.139
查「今天天气怎么样」仍返回 3 条记忆（最高相似度 0.294，无阈值）
```

时间(0.25)+频次(0.20) 权重压过相关性(0.55)、`hit_count` 只增不减、无相似度下限 —— 三个问题原样都在。**而且现在写入链路接通了，episode 会持续增长，霸榜问题会比昨晚更严重**：一条早期长摘要可以永远占着 top3。建议尽快做：相似度下限（sim < 0.35 丢弃）+ freq 权重下调或按天衰减。

### 4.2 fit 栏排序仍由简历匹配分主导，同一意图换个说法结果不同（新发现，P1）

同为「开发实习」类意图，两次检索的重叠度低：

```
I01「帮我找佛山的后端实习岗位」
    fit: 17 Java / 62 前端实习生 / 59 初级Java助理 / 10 php / 73 实习生 / 56 电商实习生
    → 关键的 55/57/61/70/30 五个开发实习岗一个都没进 top9

I05「帮我看看 Python 后端的岗位，佛山或广州都行」
    fit: 17 Java / 59 Java助理 / 57 java实习/应届 / 55 Java开发实习生 / 61 java实习生 / 32 前端
    → 57/55/61 都进了 fit
```

候选池里都有（召回层修好了），但 fit 只取 top6，排序仍按 `score + sim*10`，简历匹配分主导。**用户换个措辞，看到的岗位集合完全不同**，这会让人困惑。建议把 fit 栏排序改为「方向相似度优先、分数做组内次序」，或至少给 `sim` 更高的权重。

### 4.3 blocked 栏偶有方向不符的岗位（小）

I01 的 blocked 栏出现 9 中高级java工程师（3-5 年社招，用户找实习）—— 它是靠「Java」字面进候选的，但与「实习」意图不符。blocked 栏应该也过一遍方向检查。

### 4.4 target_roles 塞进了行业词（小）

U8 长输入抽取：`target_roles = ["产品经理","后端方向","制造业","软件公司"]` —— 制造业/软件公司是行业不是角色。抽取提示词可以补一句「行业不是 role」。

### 4.5 I10「佛山有什么岗位」仍会检索（遗留，与昨晚一致）

无方向时沿用了历史意图直接检索。缺「intent 为空则强制澄清」的兜底。

## 五、好不好用：综合评判

**打分（满分 10，按"一个 2028 届找实习的学生每天用它投简历"的标准）：**

| 维度 | 昨晚 | 今天 | 说明 |
|---|---:|---:|---|
| 听懂你（意图/槽位/多轮） | 9 | 9 | 本来就好，保持 |
| 找得准（召回与排序） | 3 | **6.5** | 召回修好了，但 fit 栏排序和跨措辞一致性还欠 |
| 记得住（画像写入+生效） | 2 | **8** | 从没接到全链路打通，且搜索不污染偏好 |
| 想得起（情节召回） | 3 | 3 | 未修，还会随记忆增多而恶化 |
| 说得清（回复诚实/卡点/缺口） | 7 | **8.5** | U3/U4/U5 的回答质量超出预期 |
| 靠谱（规则判定/不编造） | 9 | 9 | 否决双 100%，不编造 |
| **综合（日常可用度）** | **4.5** | **7** | |

**结论：可以开始每天用了，但用法要对。**

现在它擅长的事：
- 「帮我找 X 的 Y 岗位」—— 会给方向对口的 fit 栏 + 方向对但卡住的 blocked 栏，每条卡点写人话
- 说偏好（「以后只找」「不接受」「我是 2028 届」）—— 真的会记住，且搜索不会改掉它
- 问「普遍要求什么、我缺什么」—— 会做跨岗位聚合分析
- 问「为什么值得投」—— 会主动告诉你结论的不确定性

还别指望的事：
- 换个说法搜同类岗位，结果集合可能明显不同（4.2）
- 它记不住"上周聊过什么"（情节召回未修）——重要结论让它显式写进画像，或继续用工作台
- 情节记忆会随使用越积越多，霸榜问题会放大，建议两周内修掉

**下一步修复顺序**：① episode 召回权重 + 阈值（防恶化）→ ② fit 栏按方向相似度重排（防困惑）→ ③ blocked 栏过方向检查 → ④ intent 为空强制澄清。
